## 一、执行摘要

项目**已经具备一套完整的设计意图**——"深海蓝 + 青色霓虹"的 Sci-Fi 语言在 `Color.kt` 中定义得非常清晰，`EnergyBar`、`neonBorder`、渐变分隔线等细节也说明设计者是认真在做视觉体系的。

但实机验证暴露出一件事：**设计意图与最终渲染结果之间存在系统性断裂**。核心症状是三种视觉语言同屏打架：

| 视觉语言 | 来源 | 实测色值 |
|---|---|---|
| Material3 默认紫色 | 主题色板**未覆盖**的槽位回落 | `#4C3987`（顶栏）/ `#211F25`（导航栏、卡片） |
| Sci-Fi 青色霓虹 | `Color.kt` 自定义 token | `#06D6A0` / `#4CC9F0` |
| 裸硬编码色 | 散落在各页面的 `Color(0xFF...)` | `#FFA500` / `#4CAF50` |

再加上**最高频的元素（用户消息气泡）文字对比度只有 1.93:1**，整体观感是"想法很好，但没落地成系统"。

**最关键的一条结论**：这不是审美问题，而是一个可以精确定位的**主题配置缺陷**——补齐 `SciFiDarkColorScheme` 缺失的 14 个 Material3 槽位，就能一次性消除约 60% 的视觉不一致。

## 二、设计系统诊断

### 2.1 根因：色板覆盖不完整 → 紫色泄漏

`Theme.kt` 的 `SciFiDarkColorScheme` 只定义了 **13 个槽位**：

```kotlin
primary, onPrimary, secondary, tertiary, error, background,
surface, surfaceVariant, outline, outlineVariant,
onBackground, onSurface, onSurfaceVariant
```

而 Material3 的 `darkColorScheme()` 实际有 **29 个槽位**。未定义的槽位不会留空，而是回落到 Material3 baseline 默认值——**那是一套紫色系配色**：

| 未定义槽位 | 回落默认值 | 项目中出错的位置 | 实机实测 |
|---|---|---|---|
| `primaryContainer` | `#4F378B` 深紫 | `MainActivity.kt:549` 顶栏 `containerColor` | **`#4C3987`** ✅命中 |
| `surfaceContainer` | `#211F26` 紫调深灰 | `NavigationBar` 默认背景 | **`#211F25`** ✅命中 |
| `surfaceContainerHigh` | `#2B2930` | `Card` 默认容器 | 设置页卡片偏紫 |

实测统计（`scan_tokens.py`）：

```
ui_01.png  紫色像素 113,191 个  avg=#4C3987   bbox=(0,0)-(1262,1920)
ui_03.png  紫色像素 113,156 个  avg=#4C3987   bbox=(0,0)-(1262,360)   ← 精确对应顶栏区域
ui_02.png  紫色像素 195,985 个  avg=#4D3A87   bbox=(0,0)-(1262,786)   ← 顶栏 + 个人中心卡片
```

三张页面顶栏的紫色**完全一致**（`#4C3987`），证明这是同一个根因，不是页面各自的实现问题。

> 顺带说明：`Theme.kt` 里 `SciFiLightColorScheme` 定义了却从未被使用（`OpenClawTheme` 硬编码 `val colorScheme = SciFiDarkColorScheme`），`LegacyDarkColorScheme` / `LegacyLightColorScheme` / `Purple80` 等 6 个旧色值同样是死代码。

### 2.2 排版系统未建立

`ui/theme/Type.kt` 全文只有 **23 行**，只定义了 2 个槽位：

```kotlin
val Typography = Typography(
    bodyLarge = TextStyle(fontSize = 16.sp, lineHeight = 24.sp, letterSpacing = 0.5.sp),
    labelSmall = TextStyle(fontSize = 11.sp, lineHeight = 16.sp)
)
```

Material3 有 **15 个** 排版槽位，其余 13 个全部走默认。后果是页面里的字号只能靠硬编码散落：`A2UICards.kt` 中搜到 `10.sp / 14.sp / 16.sp / 18.sp / 20.sp / 24.sp / 28.sp / 32.sp` 共 8 种字号散落各处，其中 `A2UICards.kt:200` 的 `32.sp` 就是实机截图中"西安 · 天气查询"卡片文字溢出的直接原因。

另外 `letterSpacing = 0.5.sp` 对中文是反效果——中文方块字不需要额外字距，会显得松散。

### 2.3 间距 / 圆角 / 装饰组件

- **无间距 token**：DP 值全部硬编码（8/12/16/24），虽有 4dp 倍数隐式规律，但无 `Spacing` 对象约束，无法演进。
- **圆角不统一**：用户气泡 `16dp/4dp`、AI 气泡 `20dp`、输入框 `24dp`、设置卡片 `12dp`、消息卡片 `8dp`。缺少"圆角阶梯"定义。
- **4 个装饰组件是死代码**——它们定义了项目的视觉灵魂，却从未被任何界面引用：

| 组件 | 文件 | 引用情况 |
|---|---|---|
| `ParticleBackground` | `ui/components/ParticleBackground.kt` | ❌ 无任何引用 |
| `ScanLineOverlay` | `ui/components/ScanLineOverlay.kt` | ❌ 无任何引用 |
| `ShimmerEffect` | `ui/ShimmerEffect.kt` | ❌ 无任何引用 |
| `TypingCursor` | `ui/components/TypingCursor.kt` | ⚠️ 仅 import，未调用 |

这解释了为什么实机截图里完全看不到"粒子背景""扫描线"——**科幻氛围只做了一半**。真正生效的只有 `StatusIndicator`（绿点）和 `EnergyBar`（输入框能量条）。

## 三、对比度审计（WCAG AA 实测）

用 `png_probe.py` / `region_hist.py` 直接解析真机截图像素，按 WCAG 2.1 相对亮度公式计算。**AA 正文要求 4.5:1**。

| # | 元素 | 前景实测 | 背景实测 | 实测对比度 | 判定 |
|---|---|---|---|---|---|
| 1 | **用户消息气泡文字** | `#FFFFFF` | `#6BC7E0` → `#62D0B2` | **1.93:1** | ❌❌ 严重不达标 |
| 2 | 语音输入提示文字 | `#494457` | `#211F25` | **1.75:1** | ❌❌ 严重不达标 |
| 3 | 输入框占位符「输入消息...」 | `#3C4250` | `#0B0E19` | **1.91:1** | ❌ 不达标 |
| 4 | 卡片次要文字 | `#636B7A` | `#151722` | **3.32:1** | ⚠️ 不达标 |
| 5 | 导航栏标签 | `#97A2B6` | `#211F25` | 6.34:1 | ✅ 达标 |
| 6 | 顶栏标题 | `#E8DDFC` | `#4C3987` | 7.32:1 | ✅ 达标（但色相错） |
| 7 | 页面主文字 | `#E4EBED` | `#131620` | 14.96:1 | ✅ 优秀 |

### 问题 1 详解：用户气泡为什么只有 1.93:1

这是全项目**最高频、最显眼**的缺陷。`ChatScreen.kt:1370`：

```kotlin
is MessageSegment.Text -> {
    Text(
        text = segment.text,
        color = Color.White      // ← 白字
    )
}
```

而气泡背景是 `ChatScreen.kt:1324` 的亮青渐变：

```kotlin
val gradientBrush = Brush.horizontalGradient(
    colors = listOf(SciFiUserBubbleStart, SciFiUserBubbleEnd)  // #06D6A0 → #4CC9F0
)
```

实测气泡内部像素分布证实了这一点：

```
[USER_BUBBLE] region=(800,1118)-(1222,1340)
    #FFFFFF    4.2%  L=1.0000     ← 文字（纯白，与代码一致）
    #62D0B2    1.9%  L=0.5092     ← 气泡背景（青绿端）
    #6BC7E0    1.6%  L=0.4935     ← 气泡背景（冰蓝端）
```

两个背景色的亮度 L ≈ 0.49–0.51，白色文字 L = 1.0 →
`(1.0 + 0.05) / (0.4935 + 0.05) = **1.93:1**`

**修复（已有量化验证）**：文字改为深色 `SciFiOnPrimary` (#0A0E1A, L=0.0046) →
`(0.4935 + 0.05) / (0.0046 + 0.05) = **10.2:1** ✅`

即：**保留亮青色渐变（它很好看，是品牌识别），把文字从白色换成深墨蓝**。对比度从 1.93 提升到 10.2，且视觉上更"科技感"（亮青底 + 深色字是典型的赛博界面处理方式）。

### 问题 2、3 详解：alpha 衰减过头

两处都是同一个模式——用 alpha 把已定义的 token 稀释到不可读：

```kotlin
// ChatScreen.kt:768  提示文字
color = SciFiOnSurfaceVariant.copy(alpha = 0.35f)   // → 1.75:1

// ChatScreen.kt:682  占位符
color = SciFiOnSurfaceVariant.copy(alpha = 0.6f)    // → 1.91:1
```

`SciFiOnSurfaceVariant` (#94A3B8) 本身在深底上是 **7.51:1**，完全达标。**问题不在 token，在于给它叠了 alpha**。直接去掉 alpha 即可达标。

## 五、修复方案

### 修复 1（最高优先级）：补齐主题色板

在 `ui/theme/Color.kt` 追加以下 token：

```kotlin
// ==================== Material3 容器色（补齐，消除默认紫色泄漏）====================

// 主色容器 —— 深青绿底 + 高亮青绿字（对比度 9.9:1）
val SciFiPrimaryContainer        = Color(0xFF063F31)
val SciFiOnPrimaryContainer      = Color(0xFFA7F3E0)

// 次色容器 —— 深冰蓝底
val SciFiSecondaryContainer      = Color(0xFF123449)
val SciFiOnSecondaryContainer    = Color(0xFFBFE6FA)

// 三级色容器 —— 深紫底（仅作装饰点缀）
val SciFiTertiaryContainer       = Color(0xFF2A1A4D)
val SciFiOnTertiaryContainer     = Color(0xFFDCCBFF)

// 错误容器
val SciFiErrorContainer          = Color(0xFF4A1414)
val SciFiOnErrorContainer        = Color(0xFFFFD9D6)

// ==================== Surface 层级（替代 Material3 默认紫灰）====================
val SciFiSurfaceDim              = Color(0xFF070A12)
val SciFiSurfaceBright           = Color(0xFF1B2436)
val SciFiSurfaceContainerLowest  = Color(0xFF05070E)
val SciFiSurfaceContainerLow     = Color(0xFF0D1220)
val SciFiSurfaceContainer        = Color(0xFF111827)   // NavigationBar 用
val SciFiSurfaceContainerHigh    = Color(0xFF172032)   // Card 用
val SciFiSurfaceContainerHighest = Color(0xFF1E293B)   // 浮层用

val SciFiInverseSurface          = Color(0xFFE2E8F0)
val SciFiInverseOnSurface        = Color(0xFF0A0E1A)
val SciFiInversePrimary          = Color(0xFF059669)
val SciFiScrim                   = Color(0xFF000000)
```

在 `Theme.kt` 的 `SciFiDarkColorScheme` 中注册（`darkColorScheme(...)` 内追加）：

```kotlin
    // 容器色
    primaryContainer = SciFiPrimaryContainer,
    onPrimaryContainer = SciFiOnPrimaryContainer,
    secondaryContainer = SciFiSecondaryContainer,
    onSecondaryContainer = SciFiOnSecondaryContainer,
    tertiaryContainer = SciFiTertiaryContainer,
    onTertiaryContainer = SciFiOnTertiaryContainer,
    errorContainer = SciFiErrorContainer,
    onErrorContainer = SciFiOnErrorContainer,
    // Surface 层级
    surfaceDim = SciFiSurfaceDim,
    surfaceBright = SciFiSurfaceBright,
    surfaceContainerLowest = SciFiSurfaceContainerLowest,
    surfaceContainerLow = SciFiSurfaceContainerLow,
    surfaceContainer = SciFiSurfaceContainer,
    surfaceContainerHigh = SciFiSurfaceContainerHigh,
    surfaceContainerHighest = SciFiSurfaceContainerHighest,
    // 其他
    inverseSurface = SciFiInverseSurface,
    inverseOnSurface = SciFiInverseOnSurface,
    inversePrimary = SciFiInversePrimary,
    scrim = SciFiScrim,
    surfaceTint = SciFiPrimary,
```

同时清理死代码：删除 `SciFiLightColorScheme`、`LegacyDarkColorScheme`、`LegacyLightColorScheme`、`Purple80`、`PurpleGrey80`、`Pink80`、`Purple40`、`PurpleGrey40`、`Pink40`（共 9 项，约 30 行）。

**顶栏建议改法**——不要用彩色容器，改用 `surface` + 青色渐变底线，更符合 Sci-Fi 语言：

```kotlin
colors = TopAppBarDefaults.topAppBarColors(
    containerColor = SciFiBackground,
    titleContentColor = SciFiOnBackground
)
```

### 修复 7：建立排版阶梯

将 `Type.kt` 补全为完整阶梯（并去掉中文不需要的 `letterSpacing`）：

```kotlin
val Typography = Typography(
    displaySmall  = TextStyle(fontSize = 32.sp, lineHeight = 40.sp, fontWeight = FontWeight.Bold),
```
